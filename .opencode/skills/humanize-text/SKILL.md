# Humanize Text (humanizer-ru)

Локальная копия стандарта: `E:\Open Design\resources\humanizer-ru`

## Когда применять

- Пишешь НОВЫЙ русский текст для продукта (i18n-строки в `lib/i18n.ts`, SEO, лендинг, описания игр) — сразу пиши по правилам ниже.
- Редактируешь существующий русский текст — прогоняй по каталогу.
- Пользователь просит «перепиши / сделай лучше / очеловечь» — полный цикл.

## Порядок работы

1. Открой `E:\Open Design\resources\humanizer-ru\skills\humanizer-ru\SKILL.md` — это основной процесс (5 шагов + HARD BANS).
2. В режимах полного редактирования и аудита открой каталог паттернов: `skills\humanizer-ru\references\catalog.md` (58 паттернов, 13 категорий A–M).
3. Проверь `skills\humanizer-ru\edit-log.md` — накопленные правила владельца, они сильнее дефолтов.
4. Готовые промпты-команды лежат в `commands\humanize.md` и `commands\audit.md`.

## Ключевые правила (краткая выжимка)

- **HARD BANS удалять всегда**: «не просто X, а Y», «стоит отметить», «данный», «является» (>1 на 500 слов), длинное тире «—», «в современном мире», «играет важную роль», «комплексный подход», «раскрыть потенциал» и др. Полный список — в SKILL.md.
- **Факт-замок**: числа, даты, имена из исходника переносить без искажений; выдумывать конкретику запрещено. Для i18n-строк факты берутся из кодовой базы (число режимов = 32, число игроков и т.д.).
- **Регистр важнее стиля**: i18n-строки UI — короткие, не перегружай правками (<100 слов → убрать 2–3 главных маркера). SEO/лендинг — максимальная интенсивность. Юридические страницы (privacy/terms) — минимальная, только фактические ошибки.
- **Burstiness**: варьируй длину предложений; в лендинг-тексте хотя бы одно ≤4 слов на каждые 5–7.
- Не превращай живые формулировки в нейтральные (гомогенизация).

## Сканер

`skills\humanizer-ru\scripts\scan.py` требует python3 + `razdel` + `pymorphy3`. На этой машине python недоступен — работай по каталогу вручную (это штатный режим скилла). Оценку чистоты (0–100) прикидывай по логике SKILL.md: старт 100, минус за каждый hard ban и плотность маркеров.

## Специфика проекта

- Все RU-строки живут в `lib/i18n.ts` (32 режима × RU/EN). Меняя RU — не ломай EN-ключи.
- Тон бренда TUSA: дерзкий, разговорный, «свой». Это совместимо с humanizer: голос обязателен, шероховатости допустимы, канцелярит запрещён.
- После правки текстов запускать `npm run rag:build`.
